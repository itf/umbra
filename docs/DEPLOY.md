# Deploying

This is a static, offline-capable PWA. There is no server component — `npm run
build` produces a `dist/` you can host on any static host (Cloudflare Pages,
Netlify, GitHub Pages, S3, nginx, …).

---

## Build

```bash
npm run build      # wasm → worklet → icons → vite build  (output: dist/)
npm run preview    # serve dist/ locally with the right headers (see below)
```

`build` chains, in order:

1. `wasm` — compiles the Rust acoustics core to WASM (`wasm-pack`).
2. `worklet` — bundles the AudioWorklet processor (`scripts/build-worklet.mjs`).
3. `icons` — (re)generates the PWA icons (`scripts/build-icons.mjs`, see below).
4. `vite build` — bundles the four pages and emits the PWA manifest + service worker.

---

## What ships in `dist/`

| Artifact | Where | Notes |
|---|---|---|
| App shell (4 pages) | `index.html`, `editor.html`, `trainer.html`, `debug.html` | game / editor / trainer / debug |
| JS/CSS bundles + WASM | `dist/assets/*` | acoustics core WASM included |
| **HRTF dataset** | `dist/assets/hrtf/sadie_h3.hrtf` (~5.5 MB) | copied by the `copyAssets()` Vite plugin; the raw `.sofa` source is **not** shipped |
| AudioWorklet | `dist/hrtf-worklet.js` (from `public/`) | the click-free interpolating renderer |
| **PWA manifest** | `dist/manifest.webmanifest` | references the icons below |
| **Icons** | `dist/assets/icons/icon-192.png`, `icon-512.png`, `icon-maskable-512.png` | generated by `scripts/build-icons.mjs` |
| **Service worker** | `dist/sw.js` + `dist/workbox-*.js` | precaches the shell; runtime-caches HRTF/audio |
| **Host headers** | `dist/_headers` (from `public/_headers`) | COOP/COEP — see below |

After a build you can sanity-check the key paths exist:

```bash
ls dist/assets/icons/        # icon-192.png icon-512.png icon-maskable-512.png
cat dist/_headers            # the COOP/COEP block
ls dist/manifest.webmanifest dist/sw.js dist/assets/hrtf/sadie_h3.hrtf
```

## Cross-origin isolation (COOP/COEP) — only for the optional Steam Audio path

The **default game engine needs no special headers** and runs on any plain static
host. You can ignore this whole section unless you want the optional Steam Audio
backend to work in production.

The optional Steam Audio backend (`?engine=steam`) uses a threaded reflection
simulation that needs `SharedArrayBuffer`, which browsers gate behind
**cross-origin isolation** (`crossOriginIsolated === true`). That requires two
response headers on every document/asset:

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Without them, `?engine=steam` fails to initialize and **falls back to the default
engine** — the game still works, only the Steam path degrades.

- **Cloudflare Pages / Netlify**: handled automatically — we ship `dist/_headers`
  (copied from `public/_headers`), which both hosts honour.
- **Other hosts (nginx, Apache, S3+CloudFront, GitHub Pages, …)**: `_headers` is
  ignored. Send the same two headers via your server/CDN config (e.g. an nginx
  `add_header`, an Apache `Header set`, or a CloudFront response-headers policy).
  GitHub Pages cannot set custom headers, so the Steam path won't work there —
  the default game still will.

`vite dev` and `vite preview` already send these headers (see `vite.config.ts`),
so local Steam-path testing works out of the box.

## Icons

The two manifest icons (and a maskable variant) are generated programmatically by
`scripts/build-icons.mjs` — a dependency-free script (Node core `zlib` only) that
draws the sonar-ping motif and hand-encodes valid PNGs. They are written to
`assets/icons/` and copied into `dist/assets/icons/` by the build. To regenerate
them on their own: `npm run icons`.
